# 에이전트형 RAG·데이터 분석 에이전트

## 한 줄 정의

에이전트형 RAG는 언어모델이 한 번의 검색으로 끝내지 않고, 여러 단계로 검색하거나 도구(계산기, 데이터베이스 조회 등)를 호출해 가며 답을 만들어 가는 방식이다.

## 출발 질문과의 관계

한 번의 검색으로 풀리지 않는 질문(예: 여러 조항을 비교하거나, 표 데이터를 계산해야 하는 질문)에 대응하려면, 검색과 추론을 여러 번 오가며 근거를 쌓아 가는 구조가 필요하다.

## 핵심 개념 3~5개

- 다단계 검색(multi-step retrieval): 한 번 찾은 결과를 보고 부족하면 다시 검색하는 과정
- 도구 호출(tool use): 검색 외에 계산, DB 조회, 코드 실행 같은 외부 도구를 부르는 것
- 추론 흔적(reasoning trace): 다음에 무엇을 할지 스스로 판단하는 과정을 말이나 글로 남기는 것
- 정형 데이터 분석: 표나 데이터베이스처럼 구조화된 데이터를 조회·계산해 답에 반영하는 것
- 행동-관찰 루프(act-observe loop): 행동을 하고 그 결과를 관찰한 뒤 다음 행동을 정하는 반복 구조

## 대표 기법·도구

- ReAct: 추론(reasoning)과 행동(acting)을 번갈아 생성해 외부 지식·도구를 활용하는 대표적인 에이전트 프롬프트 방식 (Yao et al., 2023)
- 도구 사용 에이전트: 검색기 외에 계산기, SQL 조회, 코드 실행기 등을 함께 쓰는 에이전트 구조
- 데이터 분석 에이전트: 표·DB 형태의 정형 데이터를 코드나 쿼리로 직접 계산해 답에 반영하는 에이전트

## 품질 문서에서는?

여러 단계를 거치는 만큼, 중간 단계에서 참조한 문서 식별자와 상호참조를 끝까지 놓치지 않고 최종 답변까지 가져가야 근거가 끊기지 않는다. (일반적 문제 유형: 문서 식별자, 상호참조)

## 남은 질문

- 확인 필요: 규정·품질 문서를 다룰 때 다단계 검색이 늘어날수록 오류(잘못된 조항을 근거로 삼는 등)도 함께 늘어나는지, 이를 어떻게 점검하는지
