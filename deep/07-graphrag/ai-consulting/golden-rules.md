# 1번 AI 컨설팅 — 골든 룰 (E3)

E5에서 나오는 답이 채점 전에 지켜야 할 규칙이다. 검사 스크립트([check-golden-rules.py](../experiments/scripts/check-golden-rules.py))가 자동으로 검사한다. 2026-10-14에 정했다. 정답(기대 답) 없이 검사할 수 있는 규칙만 넣었다.

## 1. 하는 일과 하지 않는 일

- 한다: 답의 형식, 출처(원장 번호와 근거 문장)가 실제로 있는지, 스키마 목록을 지켰는지, 통제 항목에서 지어내지 않았는지 본다. 05 실험의 층위 1(규칙 기반 검사)과 같은 역할이다.
- 하지 않는다: 답이 맞는지(정답과 비교)는 채점 단계에서 따로 본다. 주장이 근거 문장에 실제로 뒷받침되는지는 판정기(층위 2)가 본다.

## 2. 답의 모양

E5에서 "검색만" 방식과 "그래프 경유" 방식 모두 같은 모양으로 답한다. 파일 하나에 질문별 답을 JSON 목록으로 담고, 칸 이름은 아래 한국어 이름 그대로 쓴다.

| 칸 | 내용 |
|----|------|
| 질문 | Q1~Q10, T1~T5 중 하나 |
| 상태 | "답함", "자료에 없음", "전제가 틀림" 중 하나 |
| 주장 | 목록. 주장마다 원장 번호(정수), 관계([스키마](schema.md) 6절 이름), 값, 근거 문장(원문 그대로) 네 칸 |
| 요약 | 사람이 읽는 답 |

- 수행 관계의 근거 문장은 [스키마](schema.md) 7절대로 "원장"이라고 써도 된다.

## 3. 골든 룰 9개

| # | 규칙 | 검사 방법 |
|---|------|-----------|
| G1 | 정해진 모양을 지킨다 | 네 칸이 모두 있고, 질문은 Q1~Q10·T1~T5, 상태는 세 값 중 하나, 주장은 목록이다 |
| G2 | 답했으면 출처가 있다 | 상태가 "답함"이면 주장이 1개 이상이고, 모든 주장의 원장 번호·관계·값·근거 문장이 비어 있지 않다 |
| G3 | 원장 번호가 실재한다 | 원장 번호가 [sources.csv](sources.csv)에 있는 번호다 |
| G4 | 근거 문장이 원문에 있다 | 근거 문장이 그 원장 번호의 원문(raw/ac-NN.txt)에 들어 있다. 비교 전에 양쪽 모두 공백·줄바꿈을 한 칸으로 줄이고, 줄 끝 하이픈 줄바꿈을 붙이고, 둥근 따옴표를 곧은 따옴표로 바꾼다. 하이픈을 붙여서 찾지 못하면 하이픈을 남긴 채로 한 번 더 본다(낱말 안 하이픈이 줄 끝에 걸린 경우). 수행 관계에서 근거 문장이 "원장"이면 G4 대신 G7로 본다 |
| G5 | 관계 이름이 스키마에 있다 | 관계가 스키마 6절 7개 이름 중 하나다 |
| G6 | 닫힌 목록 값을 지킨다 | 관계가 수행·고객 산업·적용 업무·사용 기술이면 값이 스키마 2~5절 목록 이름 그대로이거나 "기타: "로 시작한다 |
| G7 | 펌이 원장과 맞는다 | 관계가 수행이면 값이 sources.csv의 그 원장 번호 펌과 같다 |
| G8 | 통제 항목에서 지어내지 않는다 | T1·T3·T4는 상태가 "자료에 없음"이고 주장이 0개다. T2는 상태가 "전제가 틀림"이다 |
| G9 | 질문이 정한 조건을 지킨다 | Q1의 모든 주장은 원장 2번, Q2의 모든 주장은 원장 5번이다. Q3에서 관계가 사용 기술인 주장의 값은 "생성형 AI(LLM 포함)", Q4에서 관계가 적용 업무인 주장의 값은 "AI 솔루션 개발·실증", Q7에서 관계가 고객 산업인 주장의 값은 "금융"이다 |

## 4. 검사 스크립트

- 실행: 저장소 맨 위에서 `python3 deep/07-graphrag/experiments/scripts/check-golden-rules.py <답 JSON 파일>`
- 출력: 검사한 질문 수와 주장 수, 규칙별 위반 목록(질문, 주장 순번, 규칙, 이유)
- 종료 코드: 0 위반 없음, 1 위반 있음, 2 입력 오류. 질문을 하나도 읽지 못하면 2로 끝낸다. 주장이 0개인 답은 G1·G2·G8로 본다. 05 발견 6(종료 코드 0으로 조용히 실패)을 되풀이하지 않기 위해서다.
- 시험 결과: [golden-rules-test.md](../experiments/golden-rules-test.md)

## 5. 판단 기록 — AI 제안 / 내 선택 / 이유

작성: 에드워드, 2026-10-14. 1·2항은 Cowork가 사실을 정리함. 3항은 Cowork가 낸 보기 가운데 에드워드가 고른 것을 Cowork가 문장으로 이음

AI가 제안한 것: Cowork가 답의 모양과 골든 룰 9개를 제안했다. 정답 없이 검사할 수 있는 규칙만 넣고, 정답 비교와 뒷받침 판정은 채점·판정 단계로 나누자고 했다.

내가 채택하거나 고친 것: 제안대로 정했다.

그렇게 판단한 이유: 05 실험에서 번호는 맞는데 내용이 틀린 인용과, 스크립트가 조용히 실패한 일을 겪었다. 또 지어낸 인용이나 출처 없는 답을 사람이 하나하나 보기는 어렵다. 그래서 정답과 비교하기 전에 기계로 거를 수 있는 것은 먼저 거르기로 했다.

## 6. 변경 기록
