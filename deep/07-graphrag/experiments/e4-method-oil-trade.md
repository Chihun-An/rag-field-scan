# E4 측정 방법 (2번 도메인 무역 & 기름)

2026-10-22, 에이전트 그래프 1회차 전에 정했다. Cowork가 제안하고 에드워드가 골랐다.

## 대상

- 에이전트 그래프 1회차(oil-trade/agent-graph-1.csv)와 2회차(oil-trade/agent-graph-2.csv). 지시문은 [agent-graph-prompt-oil-trade.md](agent-graph-prompt-oil-trade.md)다. 원장 17편 전부에서 뽑은 그래프 전체를 비교한다.

## 비교 전 형식 검사

- 세 그래프 모두 [check-graph-csv-oil-trade.py](scripts/check-graph-csv-oil-trade.py)로 검사하고, 위반 수와 경고 수를 결과에 적는다.
- 칸이 9개가 아닌 줄(columns 위반)은 비교에서 뺀다. 다른 위반이 있는 줄은 비교에 넣는다.
- 공백을 모두 지워야만 원문에 있는 근거 문장은 위반(not-in-raw)이 아니라 경고(space-only)로 센다. 원문 파일은 PDF에서 뽑은 글자라 낱말 중간에 공백이 끼어 있기 때문이다(2026-10-22, 1회차 뒤·기준 그래프 비교 전에 더함).

## 짝짓기

1. 후보: 주어·관계·원장 번호가 같고, 정규화한 근거 문장이 같거나 한쪽이 다른 쪽에 들어 있는 두 줄. 정규화는 check-golden-rules-oil-trade.py의 normalize와 같다. 위치 칸은 쓰지 않는다.
2. 원문 용어·품목 분류 줄은 정규화한 값도 같거나 한쪽이 다른 쪽에 들어 있어야 후보다. 요건 줄은 값을 후보 조건에 쓰지 않는다.
3. 한 줄에 후보가 여럿이면 1대 1로 짝짓는다. 정규화한 값의 문자열 유사도(파이썬 difflib.SequenceMatcher의 ratio)가 높은 쌍부터 짝짓고, 유사도가 같으면 기준 그래프 줄 순서, 그다음 에이전트 그래프 줄 순서로 정한다. 닫힌 목록 칸(분류 체계·업무 단계·주체)은 짝을 고를 때 쓰지 않는다.
4. 후보가 둘 이상이었던 줄 수를 따로 센다.
5. 정규화한 근거 문장이 빈 줄은 어느 줄의 후보도 되지 않는다. 원문 용어·품목 분류 줄은 정규화한 값이 빈 줄도 그렇다. 빈 문자열은 어떤 문장에도 "들어 있다"고 계산되어, 그대로 두면 빈 줄이 같은 주어·관계·원장 번호의 모든 줄과 짝이 되기 때문이다(2026-10-22 비교 스크립트 시험에서 발견, 1회차 전에 더함).
6. 1~5번에서 근거 문장과 값을 비교할 때와 3번의 유사도를 잴 때는, 정규화한 글자에서 공백을 모두 지운 것을 쓴다. 같은 원문 문장을 골랐는데 띄어쓰기만 달라 짝이 되지 않으면, 그래프의 내용이 아니라 원문 추출 상태를 재게 되기 때문이다(2026-10-22, 1회차 뒤·기준 그래프 비교 전에 더함).
7. 원문 용어·품목 분류 줄은 1·2번에 맞지 않아도, 주어·관계가 같고 정규화한 뒤 공백을 지운 값이 완전히 같으면 후보다(근거 문장과 원장 번호는 보지 않는다). 두 관계의 값은 원문 표기 그대로라 값 자체가 같은 사실을 가리키기 때문이다. 같은 분류를 뽑고도 근거로 고른 문장이 달라 짝이 되지 않는 일을 막는다(2026-10-22, 2회차 뒤·기준 그래프 비교 전에 더함).

## 닫힌 목록 일치율 (predictions.md 3절의 E4 일치율)

- 짝 지은 줄에서 칸 단위로 잰다. 품목 분류 짝은 분류 체계 1칸, 요건 짝은 업무 단계·주체 2칸을 비교한다. 원문 용어 짝은 비교할 칸이 없다.
- 일치율 = 같은 칸 수 / 비교한 칸 수. 칸별(분류 체계, 업무 단계, 주체) 일치율도 따로 낸다.
- 한 칸에 목록 값이 여러 개면(경고 multi-value) 집합으로 비교한다. 업무 단계를 번호로 썼으면(경고 stage-number) schema.md 4절 표의 이름으로 바꿔 비교한다.
- 한쪽만 "기타: …"면 불일치다. 양쪽 모두 "기타: …"면 비교한 칸 수에서 빼고 개수를 따로 적는다.
- 관계는 짝을 지을 때 쓰므로 일치율에 넣지 않는다(predictions.md 5절).

## 참고값

- 재현율 = 짝이 있는 기준 줄 수 / 기준 줄 수. 정밀도 = 짝이 있는 에이전트 줄 수 / 에이전트 줄 수. 관계별로도 낸다.
- 정밀도는 참고로만 본다. 기준 그래프를 쓴 대화는 questions.md를 읽었으므로(worklog 2026-10-15), 기준 그래프가 질문에 필요한 줄 위주일 수 있다. 그러면 맞게 뽑은 에이전트 줄도 짝이 없을 수 있다.

## 회차끼리 일관성

- 두 에이전트 그래프끼리 위 짝짓기 규칙으로 짝을 짓는다. 자카드 지수 = 짝 지은 쌍 수 / (1회차 줄 수 + 2회차 줄 수 − 짝 지은 쌍 수). 짝 지은 줄의 닫힌 목록 칸 일치율도 같은 방식으로 잰다.
- 에이전트 그래프끼리라 디스크를 열지 않고 잰다. 1번의 자카드 지수(닫힌 목록 줄이 똑같은지)와는 정의가 다르다.

## 정답 격리

- 기준 그래프와의 비교는 handoff.md 8절 순서대로, 디스크를 연 격리 Claude Code 대화에서 비교 스크립트를 돌리고 숫자만 보고받는다.
- 비교 스크립트는 값·근거 문장·주어 이름을 출력하지 않고 개수와 비율만 낸다. 짝 목록 같은 중간 파일은 저장소에 만들지 않는다.
- 숫자만 담은 결과 파일은 저장소에 커밋한다.

## predictions.md 5절과 다른 점

- 5절은 열린 값이 같은 뜻인지 Codex가 판정한다고 정했다. 2번에서는 기준 그래프가 디스크 안에 있어 디스크를 연 동안 Codex를 쓸 수 없고, Codex 입력에 정답 내용이 들어간다. 그래서 같은 뜻 판정을 "같은 원문 문장에서 뽑은 같은 주어·관계"로 대신한다. 예측 문장은 고치지 않고, E7에 이 차이를 적는다.
- 양쪽 모두 "기타"인 칸은 Codex로 판정하지 않고 일치율에서 뺀다(1번 schema.md 8절 규칙과 다르다).

## 판단 기록 — AI 제안 / 내 선택 / 이유

AI가 제안한 것: Cowork가 짝짓기 세 안(근거 문장으로 짝짓기, Codex 판정, 둘을 섞기)을 냈다. 세부로 한 문장에서 여러 줄을 뽑았을 때의 처리, 원문 용어·품목 분류의 값 일치, 일치율 단위, 양쪽 모두 기타인 칸의 처리에 보기를 냈다.

내가 채택하거나 고친 것: 근거 문장으로 짝짓기를 골랐다. 세부는 값이 비슷한 것끼리 1대 1로 짝짓기, 원문 용어·품목 분류는 값 일치도 넣기, 칸 단위, 양쪽 모두 기타는 일치율에서 빼기를 골랐다. 모두 Cowork 추천과 같다.

그렇게 판단한 이유: 정답이 클립보드나 Codex 화면을 거치면 2번 기대 답 때처럼 또 새기 쉬우니, 새는 길을 아예 만들지 않겠다. 2번은 모든 줄에 원문 문장이 그대로 붙어 있어서, 같은 문장에서 뽑았는지로 "같은 뜻"을 대신할 수 있다. 스크립트로 재면 누가 다시 돌려도 같은 숫자가 나온다. 05 실험에서도 같은 입력의 자동 판정이 갈린 일(P29)이 있었다.
