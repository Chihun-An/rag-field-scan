# 실험 결과 01 — 층위 2 자동 판정 (조문 내용이 주장을 뒷받침하는가)

층위 1([results-01-layer1.md](results-01-layer1.md))이 조항 번호의 실재만 봤다면, 층위 2는 그 조항의 내용이 주장을 실제로 뒷받침하는지를 본다. 판정 쌍은 [pairs-01-ko.md](pairs-01-ko.md)의 P1~P8이다.

## 판정 방식

- 판정자: citation-judge 서브에이전트 ([.claude/agents/citation-judge.md](../../../.claude/agents/citation-judge.md))
- 실행 시각: 2026-10-05 10:01~10:02 +0900 (extract-doc-text.py 실행 10:01:21, 8회 판정 종료 후 확인 10:02:05)
- 호출 횟수: 8회 (쌍마다 1회, 다시 돌린 쌍 없음). 8회 모두 서브에이전트의 도구 사용 0회
- 실행 환경: Claude Code 데스크톱, 서브에이전트 모델은 호출한 세션과 같은 모델(claude-opus-5-5)
- 조문 원문: `python3 deep/05-citation/experiments/scripts/extract-doc-text.py`로 data/sanan-law.md에서 뽑음(종료 코드 0, "조문 자르기 검사: parse_law 결과와 일치 (조 11개)")
- 서브에이전트에 넘긴 것: 조문 원문, claim_ko. 이 두 개뿐이다
- 서브에이전트에 넘기지 않은 것: pairs-01-ko.md의 human 값, hypothesis, P 번호, claim_id, doc_ref. 호출 설명(description)에도 P 번호를 넣지 않았다
- 판정 순서: 8회 판정이 모두 끝난 뒤에 human 값과 비교했다. 판정 중에는 비교하지 않았다
- 중단 조건 확인: P8은 "뒷받침 안 됨", P5는 "뒷받침됨"으로 나와 중단 조건에 해당하지 않았다

### 설계 선택: 판정자 격리를 도구 수준에서 막음

citation-judge의 프런트매터에 `disallowedTools: Read, Glob, Grep, Bash, Edit, Write, NotebookEdit`를 넣어 파일 읽기 도구를 막았다. 서브에이전트 규칙에도 "results-01.md, design-01.md, pairs-01-ko.md를 읽지 않는다"고 적었지만, 글로 적은 규칙은 판정자가 어길 수 있고 어겼는지 밖에서 확인하기 어려우므로, 사람 판정과 기대 답을 아예 읽을 수 없게 도구를 막았다.

### 실행 경위: 세 번째 세션에서야 실행됨

- citation-judge는 2026-10-05 앞선 두 세션에서 로드되지 않았다. 두 번 모두 `Agent type 'citation-judge' not found` 오류로 판정 호출 0/8이었다 ([worklog.md](../../../worklog.md) 2026-10-05 "문제와 대처").
- 원인: .claude/agents/ 폴더를 새로 만든 경우 공식 문서상 재시작이 필요하다("New agents directories require a restart", https://code.claude.com/docs/en/sub-agents , 확인 2026-10-05). 기존 대화를 이어가는 것은 재시작에 해당하지 않아 폴더를 다시 읽지 않는다.
- disallowedTools는 공식 지원 필드여서 원인이 아니었다. 프런트매터를 고치지 않은 채 세 번째 세션에서 정상 로드되어 실행됐다.

### 서브에이전트 출력 원문

각 호출의 반환값을 그대로 옮겼다(서브에이전트는 P 번호를 모르므로, 쌍 이름은 호출한 쪽에서 붙였다).

- P1: `판정: 뒷받침 안 됨` / `근거: 조문은 "유해위험방지계획서를 작성할 때 ... 자격을 갖춘 자의 의견을 들어야 한다"고만 정하고, 제출이나 심사에 대해서는 정하지 않는다. 입력에 조문 번호 "제42조"도 나오지 않는다.`
- P2: `판정: 뒷받침 안 됨` / `근거: 작성·제출·심사는 ①의 "작성하여 … 제출하고 심사를 받아야 한다"에 있고, ②는 "자격을 갖춘 자의 의견을 들어야 한다"는 내용만 정한다.`
- P3: `판정: 뒷받침됨` / `근거: 조문은 "고용노동부장관에게 제출하고 심사를 받아야 한다"는 제출 의무와 자격자 의견 청취만 정하고, 미제출 시 과태료 금액은 적혀 있지 않다.`
- P4: `판정: 뒷받침됨` / `근거: 조문의 "위험성평가의 방법, 절차 및 시기, 그 밖에 필요한 사항은 고용노동부령으로 정한다"가 주장 문장과 글자 그대로 같다.`
- P5: `판정: 뒷받침됨` / `근거: 조문의 "근로자는 제38조 및 제39조에 따라 사업주가 한 조치로서 고용노동부령으로 정하는 조치 사항을 지켜야 한다"와 주장은 어순만 다르고 뜻이 같다.`
- P6: `판정: 뒷받침됨` / `근거: 조문의 "“근로자”란 「근로기준법」 제2조제1항제1호에 따른 근로자를 말한다"가 주장의 정의 내용과 글자 그대로 같다. 다만 주장의 "이 법에서"라는 적용 범위 표현은 입력 조문에 없다.`
- P7: `판정: 뒷받침 안 됨` / `근거: 조문에는 "사업장의 산업재해 예방계획의 수립에 관한 사항"이라는 항목만 있고, 누가 이 사항을 맡는지(안전보건관리책임자)와 무엇을 해야 하는지(총괄하여 관리)는 나오지 않는다.`
- P8: `판정: 뒷받침 안 됨` / `근거: 조문에는 "건설공사를 착공하려는 경우" 계획서를 제출하고 심사를 받아야 한다는 내용만 있고, "착공일부터 30일 이내"라는 제출 기한은 조문 어디에도 없다.`

참고: extract-doc-text.py는 항·호만 뽑을 때 조 번호 줄을 붙이지 않는다. 그래서 P1 근거에 "입력에 조문 번호 '제42조'도 나오지 않는다"는 문장이 들어갔다. 이 점이 P1 판정에 얼마나 영향을 줬는지는 확인 필요.

## 자동 판정과 사람 판정이 갈린 쌍

### P7 (제15조 제1항 제1호, Q2)

- 자동 판정: 뒷받침 안 됨 / 사람 판정: 맞음
- pairs-01-ko.md의 hypothesis 인용:

> 의무를 지우는 문구("총괄하여 관리한다")는 제15조 제1항 본문에 있고 제1호에는 없다. 호만 떼어 주면 주장의 일부만 뒷받침된다. 청크 경계가 근거를 끊는 경우다.

## P1과 P2 비교

P1(제42조 제2항만)과 P2(제42조 제1항+제2항)는 같은 주장에 문서 범위만 다르다. 판정은 갈리지 않았다. 둘 다 "뒷받침 안 됨"이다.

pairs-01-ko.md의 P2 hypothesis는 조 전체를 주면 판정기가 항을 구분하지 못하고 "뒷받침됨"으로 볼 수 있다고 봤다. 이번 실행에서 citation-judge는 P2에서 "작성·제출·심사는 ①에 있고 ②는 의견 청취만 정한다"고 항을 구분해 판정했다. 다만 쌍마다 한 번씩만 돌렸으므로, 같은 입력을 여러 번 돌려도 같은 값이 나오는지는 확인하지 않았다.

## 한계

1. 판정기(citation-judge)는 results-01.md의 답변을 만든 것과 같은 모델 계열이다. 자기 답을 관대하게 볼 편향이 있을 수 있다.
2. 서브에이전트를 썼지만 완전히 독립된 판정자는 아니다. MiniCheck 같은 외부 모델로 교차 확인하지 못했고, 그 이유는 [worklog.md](../../../worklog.md) 2026-10-04 기록(MiniCheck 설치·실행 기록)에 있다.
3. 판정이 "뒷받침됨"과 "뒷받침 안 됨" 두 값뿐이어서, P3처럼 "문서에 없음"이라는 부정 주장인 경우를 제대로 담지 못한다. 이번 P3는 "뒷받침됨"으로 나왔지만, 근거는 과태료 금액이 조문에 "적혀 있지 않다"는 것이다.
